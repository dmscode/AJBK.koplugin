# AJBK.koplugin（AI 基百科）

**AJBK = 「AI 基百科」**——用 AI 替代维基百科：把大语言模型当作字典、词典，
在阅读中一键查询生僻字、短语、典故的读音与简明释义。

**定位是本地词典的后备查询工具**。日常查词仍用 KOReader 自带词典；当词典查不到——
生僻字、网络新词、文言短句、成语典故——或者维基百科不可达时，用 AJBK 直接问 AI。

与内置维基百科**并存**（不替换、不修改 KOReader 源码），全部使用官方插件 API。
只做释义问答这一个点，**极致性能优先**：默认关闭思考、一次性小响应，
适合低内存电纸书设备。

## 特性

- 三个查询入口：查词窗口按钮（与 Wikipedia 同级）、选中文字弹窗、手动输入词语
- 19 家预设 AI 提供商（国内/国际站分列）+ 自定义提供商（OpenAI 兼容接口，本地 Ollama / LM Studio 亦可）
- 模型列表从服务器拉取点选，拉取失败可手动输入；**填写配置时即可点"测试"验证**
- 思考模式：默认关闭（响应最快），可调 低 / 中 / 高；当前提供商不支持时自动禁用
- **上下文感知**：自动带上前后文、所在整句、书名/作者/章节，把"选偏了的词"还原成本意
- **选区自检**：电纸书上经常只选中一个词里的半个字，此时自动提示模型分层解释——先解释选中的片段，再解释它最可能所属的完整词条
- 系统提示词完全可自定义，支持 **20 个占位符**（选中内容、上下文、书名、作者、章节、日期……）
- 配置存于 KOReader **设置目录**（`ajbk_config.lua`），重装/升级插件不丢；删除插件时由插件管理器一并清理
- 思考内容永不显示；结果为纯文本，直接进 KOReader 原生查询窗口

## 安装

把整个 `AJBK.koplugin` 文件夹复制到 KOReader **用户插件目录**，重启 KOReader：

- Kindle/Kobo 等一般是 `<存储分区>/.adds/koreader/plugins/`
- 或者在 KOReader 设置中配置 `extra_plugin_paths` 指向任意目录

安装后在 工具 → 更多工具 → 插件 中确认「AJBK（AI 基百科）」已启用。

## 快速上手

1. 菜单 → **搜索** → AJBK → **提供商与模型** → 添加预设提供商
   （推荐"硅基流动（国内）"，也可以添加自定义提供商）。
2. 在弹出的 API Key 对话框中填写（输入框已按密码掩码显示），点 **测试** 确认"连接成功"，然后保存。
3. 回到该提供商子菜单，点 **测试连接并获取模型列表**，从列表中点选一个模型。
4. 完成配置——阅读中选中文字即可查询。

## 查询入口

| 入口 | 操作 | 场景 |
|---|---|---|
| 查词窗口按钮 | 选中文字查词后，点窗口底部的 **AJBK** | 词典查无结果时的顺手后备；按钮可自定义（见下） |
| 选中文字弹窗 | 长按划选，在菜单末尾点 **AJBK**（"翻译"之后） | 不想先查词典，直接问 AI |
| 手动查询 | 菜单 → 搜索 → AJBK → 查询词语 | 想查的词不在书里（阅读器与文件管理器均可用） |

**自定义词典卡片底部按钮**：AJBK 与 词典 / Wikipedia / 翻译 等按钮一样，可以重新排列、显示或隐藏——
路径：**搜索设置（放大镜图标）→ 设置 → 词典设置 → 自定义按钮 → 排列并切换按钮**。
比如平时把 AJBK 排在"词典"旁边方便后备查询，或暂时隐藏它，都在这里完成。

## 上下文与选区自检

电子墨水屏上用划选定位一个词并不容易：容易只选中其中一个字，或多带进一个标点，
也可能整体偏了一两个字。AJBK 不再"只把选中的字符串扔给模型"，而是：

1. **清洗**：与内置词典一致，走 `dictionary:cleanSelection`（去标点、去 `·|↑ˈˌ`、
   去英文所有格与法语 `l'`/`qu'` 前缀），再取紧贴选区的字符做粘连判断。
2. **前后文**：`getSelectedWordContext` 取前后各 6 个词（各截断 120 字），
   用 `【选区】` 标出在原文里的位置；`extendXPointersToSentenceSegment` 取整句（截断 200 字）。
   提示词里同时给出「原文」（整句）和「前后文」，模型能据此判断词性与义项。
3. **选区自检**：读紧贴选区左右各一个字符，如果它们仍是词内字符，就说明选区把词切开了：
   - 中文：只选中 1 个字，或 2 个字且两侧都粘连 → 疑似半个词；
   - 西文：任一侧粘连 → 疑似半个词（两侧都粘连反而说明正好选成一个整词）。
   > 只选中 1 个字且不粘连时（"的""了"这类独立成词的常见字），也会提示模型
   > "若该字更常作为多字词的一部分出现，请在解释本字之后列出常见词条"。
4. **元数据**：书名、作者、丛书、文档语言、章节标题、页码、总页数、阅读进度一并送入。
   古文、专业书、小说对同一个词的解释偏好不同，这些信息比多给几个 token 更有用。

PDF 与非 reflow 文档没有 xpointer 与上下文接口，此时相关字段为空，
`renderPrompt` 会把整行删掉——提示词不会出现「原文：」后面空一格的情况。

## 设置（菜单 → 搜索 → AJBK）

| 设置 | 说明 |
|---|---|
| 提供商与模型 | 合并管理：添加预设或自定义提供商；每家提供商子菜单内含当前模型、测试连接并获取模型列表、手动输入模型名、设为当前、修改 Key/地址（对话框内均有"测试"按钮）、删除 |
| 思考模式 | 关闭（默认）/ 低 / 中 / 高；按提供商自动映射为各家参数，未支持的提供商档位置灰 |
| 目标语言 | 释义用哪种语言回答（默认简体中文），与原文语言无关；可选"跟随原文" |
| 系统提示词 | 默认模板见下；可编辑、插入占位符、恢复默认 |

连接测试 = `GET {base}/models`：成功即说明地址与 API Key 有效，同时返回模型列表。

## 默认提示词

```
你是电子墨水阅读器里的词典。直接给答案，不要寒暄，不要复述问题。

书籍：{{title}}
作者：{{authors}}
章节：{{chapter}}
原文：{{sentence}}
前后文：{{context}}
选区：{{selection}}
{{fragment_note}}

要求：
1. 先给读音：中文用带声调的拼音，其他语言给原文拼写或音标。
2. 给出该词在「原文」这句话里的词性，只解释与语境相符的义项，不超过三行。
3. 若有「选区自检」提示，说明选区可能不完整：先解释选区本身，再解释它最可能所属的完整词条。
4. 用{{target_language}}解释；原文里的专名可保留原写法。
```

**渲染规则**（`AjkbSettings.renderPrompt`）：

- `{{key}}` 替换为对应值；`{{word}}` 是 `{{selection}}` 的旧别名，兼容 v0.1 的模板。
- **某个占位符没有值时，它所在的那一行会被整行删掉**，不会留下「书名：」这种空壳。
- 模板里出现未知的占位符名（拼错了）时，**原样保留**，方便一眼看出问题。

### 可用占位符

| 占位符 | 含义 |
|---|---|
| `{{selection}}` | 选择内容（已清洗标点） |
| `{{selection_chars}}` | 选中字数 |
| `{{context}}` | 上下文，选中位置用 `【】` 标出 |
| `{{context_before}}` / `{{context_after}}` | 前文 / 后文（单独使用） |
| `{{sentence}}` | 选区所在的整句 |
| `{{fragment_note}}` | 选区自检提示，选完整时为空（整行删除） |
| `{{title}}` | 书名 |
| `{{authors}}` | 作者 |
| `{{series}}` | 丛书名 |
| `{{language}}` | 文档语言代码 |
| `{{chapter}}` | 章节名（当前页所属目录项） |
| `{{page}}` / `{{pages}}` / `{{percent}}` | 当前页 / 总页数 / 阅读进度 |
| `{{date}}` / `{{time}}` | 当前日期（带星期）/ 时刻 |
| `{{provider}}` / `{{model}}` | 当前提供商 / 模型名 |
| `{{target_language}}` | 目标语言（设置项，默认中文） |

菜单里的 **插入占位符** 会列出这 20 项，点一项即把 `{{key}}` 追加到提示词末尾，
再手动挪到想要的位置（文本框支持多行编辑）。

### 目标语言

`设置 → 目标语言` 决定释义用哪种语言回答，跟书里原文的语言**无关**——
读英文书也想看中文解释，选中文即可（默认值）。

- 只有三项：**中文** / **英文** / **自定义…**
- 自定义里直接写语言名即可，例如 `日文`、`繁體中文`、`Deutsch`——语言名本身就是自然语言，
  AI 看得懂，不需要枚举一长串；留空保存则恢复默认（中文）
- 值以 `{{target_language}}` 注入模板，默认模板第 4 条即「用{{target_language}}解释」
- 只影响释义语言；读音、词性仍按原文处理

## 性能设计（低内存设备）

- 不做流式、不做多轮历史；查询期间只有一个可点按取消的进度框。
- 网络请求在 **Trapper 可取消子进程**中执行：请求期间 UI 保持响应，取消即终止子进程。
- 结果复用原生查询窗口渲染，无自制 Markdown/HTML 渲染器；输出剥离思考块与 Markdown 符号后为纯文本。
- 上下文与元数据都有硬上限（前后文各 120 字、整句 200 字），选区只在超过 1000 字符时才截断，
  不随书籍大小增长；`max_tokens=1024`、`temperature=0.2`、默认 reasoning 关闭；
  服务端若明确拒绝这两个采样参数（OpenAI o 系、gpt-5 一类），会自动去掉后重试一次。
- Widget 全部惰性加载；配置为设置目录内单一文件（`ajbk_config.lua`，LuaSettings 格式，可手工编辑）。
- HTTP/HTTPS 走 `socket.http` + `socketutil.table_sink`：本地 `http://` 服务可用，
  并且**总超时真的生效**（`ltn12.sink.table` 不执行总超时，只有 socketutil 的 sink 才会）。

## 发布

发布即打标签，其余全自动（结构参照 assistant.koplugin 的 release workflow）：

```bash
git tag v0.1.0
git push origin v0.1.0
```

GitHub Actions（[.github/workflows/release.yml](.github/workflows/release.yml)）会依次：

1. 运行桌面测试（84 项语法与纯函数检查，不通过则中止发布）；
2. 用 `git archive` 组装 `AJBK.koplugin/` 目录——`.gitattributes` 中的 `export-ignore`
   自动排除 docs/、tests/、CI 配置；
3. 把 tag 版本号写入 `_meta.lua` 的 `version` 字段；
4. 打出 `AJBK.koplugin-v0.1.0.zip` 并创建 GitHub Release（自动生成 Release Notes）。

`workflow_dispatch` 手动触发是**干跑**：只跑测试、组装并上传 artifact，
不写版本号、不创建 Release（分支上创建 Release 会因没有 tag 而失败）。

用户从 Releases 下载 zip，解压到 KOReader 插件目录即可完成安装。
仓库根目录即插件目录，本地尚未初始化 git 时，`git init` 后直接推送即可。

## 工作原理

实现依据与源码行号详见 [docs/技术调研.md](docs/技术调研.md)；需求决议见
[docs/需求文档.md](docs/需求文档.md)；历史问题清单与修复状态见

- 入口注册走官方 API：`ReaderDictionary:addToDictButtons`、`ReaderHighlight:addToHighlightDialog`、
  主菜单 `sorting_hint = "search"`。

  提示词模板渲染 → 子进程请求（OpenAI 兼容 `chat/completions`）→ 纯文本后处理 → 原生 `showDict` 窗口展示。
- 预设提供商接入点核实于 2026-09-29，国内/国际站 API Key 互不通用，故分列（见技术调研 §8）。

## 目录结构

```
AJBK.koplugin/
├── .github/workflows/release.yml  自动打包发布（v* 标签触发；手动触发为干跑）
├── .gitattributes                 归档排除规则（docs/tests/CI 不进发布包）
├── .gitignore                     排除本地配置残留与 Python 缓存
├── _meta.lua                      插件元信息（发布时自动写入版本号）
├── main.lua                       入口：三个挂载点 + 查询编排 + 设置菜单
├── ajbk_presets.lua               19 家预设提供商（含国内/国际双端点）
├── ajbk_context.lua               上下文与元数据采集（前后文、整句、选区自检）
├── ajbk_settings.lua              设置读写 + 提示词模板渲染
├── ajbk_net.lua                   网络与解析层（纯函数，可在子进程运行）
├── docs/                          需求文档、技术调研、代码审查报告
└── tests/ajbk_test.py             桌面端验证脚本（路径无关，本地与 CI 均可运行）
```

配置不在插件目录：`<KOReader 设置目录>/ajbk_config.lua`（首次保存设置后生成）。
升级插件时旧位置（插件目录内）的配置会被**自动搬迁一次**。

## 已知限制 / 待真机验证

- 尚未在真机上跑过完整查询：v0.2.0 已部署到 Kindle（`koctl deploy`，设备端 LuaJIT 语法自检通过），按钮注册、菜单交互、子进程取消仍需实际按一遍（桌面端已通过 84 项语法与纯函数测试）。
- 上下文与选区自检依赖 reflow 文档（EPUB 等）的 xpointer 接口；PDF、以及从文件管理器手动查询时相关字段为空，提示词自动省略这些行。
- 预设中的 `default_model` 仅为初始预填，模型名可能随平台更新过时，请以"测试连接并获取模型列表"为准。
- xAI / MiniMax / Gemini 兼容层 / 火山方舟 的思考参数映射标注为"待实测"（不阻塞使用，失败时自动走手动输入与参数省略）。
- Ollama 的 OpenAI 兼容层对 `enable_thinking` 会报错：本地思考模型请选非思考版本，`<think>` 内容会被自动剥离（含多行与未闭合标签）。
- 思考内容永不显示、也不提供显示选项（字典场景无此需要）。
