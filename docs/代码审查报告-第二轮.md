## 一、P1（会静默丢数据或给出错误结论）

### P1-1 保存探针查的是目录，落盘写的是文件（`ajbk_settings.lua:133-158`）

`storageWritable()` 往 `path .. ".probe"` 写一个探针文件，以此判断"设置目录可写"；而 `S():flush()` 真正写的是 `path` 本身。

- 文件 `ajbk_config.lua` 只读、目录可写时：探针成功 → `save()` 返回 true → 界面提示"已保存" → 文件其实没变。
- 反过来的情况（目录只读）探针能拦住，所以这不是完全没用的检查，但恰好漏掉了最容易发生的一种：老配置文件被同步工具/备份脚本改成只读。

```lua
-- 建议：探针直接打在被写的那个文件上，语义才对得上
local function fileWritable(path)
    local f = io.open(path, "a")   -- 文件只读时这里就失败
    if not f then return false end
    f:close()                      -- 不写入，mtime 不变
    return true
end
```

依据：`util.writeToFile` 打不开文件只 `logger.warn` 并返回 false（`F:\ForAI\koreader\frontend\util.lua:1124` 起），`LuaSettings:flush` 又把返回值吃掉，所以插件只能自己探。

### P1-2 添加提供商忽略了落盘结果（`ajbk_settings.lua:182-195`、`main.lua:595-611`）

`addProvider` 调了 `saveProviders()`（它返回 `save()` 的布尔值），但**丢弃**，一律 `return provider`。于是目录只读时走这条链：

1. 用户填完自定义提供商 →
2. `addProvider` 返回 provider（成功）→
3. `main.lua:611` 提示"已添加「X」" →
4. 重启后提供商消失。

`updateProvider` / `removeProvider` / `setPrompt` 都正确回传了布尔值，只有 `addProvider` 漏了，属实现不一致。

```lua
    if not AjbkSettings.saveProviders(providers) then
        return nil, "unwritable"
    end
```

调用处按 `err == "duplicate"` / 其他分别提示。

## 二、P2（用户能感知到的功能缺陷）

### P2-1 查询的选区被截到 200 字符，模型答的不是全文（`ajbk_context.lua:24`、`:104`、`:113`）

`{{selection}}` 就是"要查的那个词"，但 `buildPrompt` 用的是 `vars.selection = clip(selection, 200)`。选中一整段（e-ink 上很常见，尤其是想查整句意思）时，提示词里的"选区"是被截断并加了 `…` 的版本，而结果窗口标题 `main.lua:222` 显示的是全文 —— 模型解释的和标题写的不是同一个东西。

`selection_chars` 同样按截断后的文本计数（`:113`），会报 200 而不是真实字数。

建议：上下文可以考虑截断，**被查询的正文不截断**。

```lua
    selection = type(selection) == "string" and util.trim((selection:gsub("%s+", " "))) or "",
    ...
    vars.selection_chars = tostring(charCount(vars.selection))
```

真担心提示词过长的话，上限放到 1000 字符左右并在 `{{selection_chars}}` 上说明，而不是静默改文本。

### P2-2 「选区自检」把中文标点当成词内字符，句末几乎必然误报（`ajbk_context.lua:52-61`）

```lua
local function isWordChar(c)
    if util.isCJKChar(c) then return true end   -- ← 问题在这
    return c:match("^[%a%d]$") ~= nil
end
```

`util.isCJKChar` 的范围是 `0x2E80–0x9FFF`、`0xFE30–0xFE4F`、`0xFF00–0xFFEF`（`F:\ForAI\koreader\frontend\util.lua:537-555`），**其中包含 CJK 标点**：`U+3002 。`、`U+3001 、`、`U+FF01 ！`、`U+FF1F ？`、`U+FE30…` 全部命中。

实测推演：正文"他说你好。"，用户选中"你好"（完整的两字词）——
左侧 `说` 是词内字符 → `glued_left = true`；右侧 `。` 也被判成词内字符 → `glued_right = true`；`n = 2` 命中"中文两侧都粘连"分支 → 生成"本次只选中 2 个字符……很可能只是词的一部分"，模型于是先解释"你好"再额外铺开三五个词条。**这是最常见的使用场景，误报率不低。**

反向漏判：`c:match("^[%a%d]$")` 在 Lua 的 C locale 下只认 ASCII，`é`、`ü`、`đ` 都返回 false → 法语/德语/越南语书里真的被切开的词（"était" 只选到 "tait"）不会触发自检。

建议：词内字符 = 「不是空白、不是标点」，标点判定要把 CJK 段一起覆盖：

```lua
local CJK_PUNCT = "。、，；：！？…—·「」『』（）【】〈〉《》〔〕“”‘’"
local function isWordChar(c)
    if type(c) ~= "string" or c == "" then return false end
    if c:match("^%s$") or c:match("^[%p]$") then return false end
    if CJK_PUNCT:find(c, 1, true) then return false end
    -- 全角数字/字母仍是词内字符，需要保留，所以不能简单用 isCJKChar 反选
    return not c:match("^[%z\1-\127]+$") or c:match("^[%a%d]$") ~= nil
end
```

（若想更严格，可用 `F:\ForAI\koreader\frontend\ffi\util.lua` 的 `utf8charcode` 把码位解出来，排除 `0x2000–0x206F`、`0x3000–0x303F`、`0xFE30–0xFE4F` 与全角标点区间。）

### P2-3 字符串入参的旧路径会漏出字面占位符（`ajbk_settings.lua:341-346`）

`buildPrompt(vars)` 兼容字符串入参时只填了 `{ selection = word }`，而 `renderPrompt` 的规则是"vars 里**没有**的键原样保留"。于是 `buildPrompt("hello")` + 默认模板实际产出：

```
书籍：{{title}}
作者：{{authors}}
章节：{{chapter}}
原文：{{sentence}}
前后文：{{context}}
选区：hello
{{fragment_note}}
```

（已用 lupa 实跑确认。）当前 `main.lua:188` 走的是 table 路径，所以这条不致命，但它是一个**公开 API 的默认行为**，测试 `tests/ajbk_test.py:237` 也没覆盖——那里用的模板只有 `{{selection}}`，把问题盖住了。

修法：把"已知但有值缺失"和"根本不认识的键"分开。`PLACEHOLDERS` 已经是现成的已知集合：

```lua
local KNOWN = {}
for _, ph in ipairs(AjbkSettings.PLACEHOLDERS) do KNOWN[ph.key] = true end
KNOWN.word = true

local v = vars[key]
if v == nil and not KNOWN[key] then
    return "{{" .. key .. "}}"   -- 真·拼写错误，保留提示用户
end
```

### P2-4 子进程丢返回值时，用户看到的是 `%1`（`main.lua:647`、`:649`、`:678`）

`Trapper:dismissableRunInSubprocess` 在子进程没有输出时只返回 `completed`（`F:\ForAI\koreader\frontend\ui\trapper.lua:679-686`，`ret_values == nil`），调用方得到的 `ok` 是 `nil`。这三处直接把 `result` / `models_or_err` 塞进 `T(...%1...)`：

```lua
self:showInfo(T(_("测试失败：\n%1"), result), 8)
```

而 `util.template` 用的是**函数替换**（`F:\ForAI\koreader-base\master\ffi/util.lua:785-794`），`gsub` 的替换函数返回 nil 时就保留原匹配 —— 实测 `T("失败：%1", nil)` 输出字面 `失败：%1`。用户看到的是"测试失败：%1"，完全无法自查。

`main.lua:209` 已经做对了（`content or _("（未知错误）")`），这三处照抄即可。另外 `:647` 的 `#result` 在 `ok == false` 分支不会执行，但若将来 trapper 语义变化会直接抛错，顺手写成 `type(result) == "table" and #result or 0` 更稳。

### P2-5 地址规范化放过了"少一个斜杠"和"本机地址"（`ajbk_net.lua:44-56`）

lupa 实测（`normalizeBaseUrl`）：

| 输入 | 输出 | 评价 |
| --- | --- | --- |
| `localhost:11434` | `https://localhost:11434` | 本机明文服务 → TLS 握手失败 |
| `192.168.1.9:8080/v1` | `https://192.168.1.9:8080/v1` | 同上 |
| `http:/host` | `https://http:/host` | 把 `http:` 当成了主机名 |

两个成因：

1. `:44` 的 `^(%a[%w+.-]*)://(.*)$` 要求完整 `://`，`http:/host` 匹配失败后被当成"没写协议"，前面补 `https://`；随后 `:54` 的 `^https?://([^/]+)` 抓到的主机恰好是 `http:`，于是通过了主机校验。
2. `:51-52` 无协议时一律补 `https://`。用户对着 Ollama/LM Studio 的文档照抄 `localhost:11434`，得到的是"Cannot connect"，而不是"你该写 http://"。

建议：

```lua
    -- 少了 // 的协议前缀基本是笔误，直接指出来比猜意图好
    if url:match("^%a[%w+.-]*:/[^/]") or url:match("^%a[%w+.-]*:$") then
        return nil, _("API 地址格式不对：协议后面需要 ://，例如 https://api.example.com/v1。")
    end
    ...
    local host = url:match("^https?://([^/:]+)")
    ...
    -- 本机/内网默认走 http：这些地址上跑的几乎都是明文服务
    if not scheme then
        local localish = host == "localhost" or host == "127.0.0.1"
            or host:match("^10%.") or host:match("^192%.168%.")
            or host:match("^172%.([1-2]%d|3[01])%.")
        url = (localish and "http://" or "https://") .. url
    end
```

### P2-6 首行的 Markdown 标题剥不掉（`ajbk_net.lua:136-138`）

```lua
text = text:gsub("\n#+%s*", "\n")
```

模式以 `\n` 开头，`"# 释义\n正文"` 首行的 `# ` 原样留着（实测）。模型很爱这么开头，结果第一行就是 `# 释义`。

```lua
text = text:gsub("^#+%s*", ""):gsub("\n#+%s*", "\n")
```

### P2-7 固定发 `max_tokens` + `temperature`，OpenAI 推理模型必 400（`ajbk_net.lua:215-223`）

`stream`/`max_tokens`/`temperature` 三件套是写死的。OpenAI 的 o 系列与 gpt-5 只接受 `temperature = 1`，且不接受 `max_tokens`（要 `max_completion_tokens`），一次 400 直接失败；而 `presets.lua` 里 OpenAI 条目正是 `reasoning_effort` 风格，用户选"中/高"时就踩上了。

建议：把"参数不被接受"当成可恢复错误，去掉这两个字段重试一次（同一请求、只改 body），错误信息里带上原始 400 便于判断：

```lua
    -- 400 且提到 temperature/max_tokens：极可能是推理模型，去掉这两个再试一次
```

## 四、本轮确认"不是问题"的（避免下轮误改）
