# AJBK.koplugin 需求文档

> AJBK = 「AI 基百科」。以 KOReader 插件形式**新增** AI 查询能力：在查词窗口注册与"维基百科"同级的 AJBK 按钮，在选中文字菜单注册入口；点击后携带系统提示词向 AI 提问并展示解释。**与内置维基百科并存，不替换、不修改 KOReader 源码。**
> 技术实现依据见 [技术调研.md](./技术调研.md)。

## 1. 背景与目标

KOReader 在阅读中选中文字后，可查词典、跳维基百科。国内访问维基百科不便，而对生僻字、成语、文言短句这类需求，AI 释义更直接。

**命名与定位**（2026-09-30 明确）：AJBK = 「AI 基百科」——用 AI 替代维基百科。AJBK 是**本地词典的后备查询工具**：日常查词仍用自带词典；词典查不到的生僻字、网络新词、文言短句、成语典故，或维基百科不可达时，用 AJBK 直接问 AI。

目标：开发 KOReader 插件 `AJBK.koplugin`，在 KOReader 的查询体系中注册 AJBK 入口——用户选中文本后一键向 AI 提问，在原生查询窗口中查看释义。与维基百科并存，用户可各取所需。

**产品定位**（2026-09-29 拍板）：只聚焦一个点——**把 AI 当字典、词典用**，做生僻字、短语、短句的释义问答。不做对话、不做多轮、不做搜索、不做书籍分析（这正是与 assistant.koplugin 等全能型 AI 插件的差异）。一切设计以**极致性能**为先，确保低内存电纸书设备舒适使用：默认不开思考（可配置）、默认不带上下文、一次性小响应、全部复用 KOReader 原生窗口。

## 2. 功能需求

### 2.1 查询入口（三处注册）

1. **查询窗口按钮**（主入口）：查词结果窗口底部注册与 Wikipedia 同级的 AJBK 按钮。走 KOReader 官方按钮注册 API，参与"自定义窗口按钮"体系——用户可在设置中像内置按钮一样勾选、排序或移除它（路径：搜索设置 → 设置 → 词典设置 → 自定义按钮 → 排列并切换按钮）。
2. **选中文字弹窗**：长按划选后弹出的操作菜单（选择/高亮/复制/加注/维基百科/词典/翻译…）末尾注册 AJBK 项。
3. **设置菜单查询入口**（可选，P2）：设置里提供"AJBK 查询"，手动输入词语查询（对齐维基百科 lookup 的体验）。

### 2.2 核心查询流程

1. 点击 AJBK 入口后，将选中文字作为提问内容，**携带系统提示词与阅读上下文**向所配置的 AI 提供商发起请求。
2. 请求期间显示进度提示（可取消）；离线时提示需联网（跟随 KOReader 网络管理，联网后可自动重试）。
3. 请求完成后，在 KOReader 原生查询结果窗口中展示 AI 的解释（样式与词典/百科结果一致，来源名显示为 AJBK）。
4. 请求失败（网络错误、超时、鉴权失败等）时给出可读的错误提示。

场景：生僻字读音字义、成语/短语/典故解释、文言文短句释义等。

#### 2.2.1 阅读上下文（2026-10-24 新增）

电子墨水屏上划选定位一个词并不容易：容易只选中其中一个字、多带进一个标点，或整体偏移一两个字，
反复重选成本高。因此查询请求默认携带一定上下文，用于还原用户真实意图与词的语境：

- **前后文**：`getSelectedWordContext` 取选区前后各 6 个词（各截断 120 字），提示词中以 `【选区】` 标出位置。
- **整句**：`extendXPointersToSentenceSegment` 把选区扩展到句末标点，得到整句（截断 200 字）。
- **元数据**：书名、作者、丛书、文档语言、章节标题、页码/总页数/阅读进度、当前日期。
- **选区自检**：读取紧贴选区左右各一个字符，判断选区是否切开了一个词
  （中文：1 字恒可疑；2 字且两侧粘连可疑。西文：单侧粘连可疑），
  可疑时自动生成提示，要求模型**分层解释**：先解释选区本身，再解释它最可能所属的完整词条。
- 所有上下文均有硬上限，不随书籍大小增长；PDF 等无 xpointer 接口的文档相关字段为空，提示词自动省略整行。

因选中内容可能被清洗（去标点等）而不等于屏幕上的原文，自检依据**原始选区坐标**，不依据清洗后的字符串。

### 2.3 插件设置菜单

**位置**：顶部菜单 → **搜索** → **AJBK（AI 百科）**（与 词典查询/维基百科查询/生词本 同级，两层可达；`sorting_hint = "search"`，2026-09-29 调整——原"工具 → 更多工具"过深）。界面组件映射与技术选型见 [技术调研.md](./技术调研.md) §7，预设提供商清单见 §8。

包含：

#### 2.3.1 提供商与模型（合并为一个子菜单）

- **预设提供商**：内置 19 家预设（国内/国际站分列），选择后自动填充 API Base URL，用户只需填 API Key。
- **自定义提供商**：可自行填写名称、API Base URL、API Key。
- 接口约定：统一采用 **OpenAI 兼容接口**（`POST {base}/chat/completions`、`GET {base}/models`）。
- 每家已配置提供商一个子菜单，内含：当前模型展示、**测试连接并获取模型列表**（兼 API 配置测试）、手动输入模型名、设为当前提供商、修改 API Key / API 地址、删除。
- **连接测试**：`GET {base}/models`，成功即说明地址与 Key 有效；填写 API Key、API 地址、自定义提供商的对话框内均提供**测试按钮**，可在保存前验证输入值（2026-09-29 增补）。
- 模型列表拉取失败（无网络、地址错误、不支持该接口）时，允许**手动输入模型名**；记住每个提供商上次使用的模型。

#### 2.3.2 系统提示词与占位符（2026-10-24 重做）

- 内置**默认提示词**（用户可查看、编辑、插入占位符、恢复默认）。默认模板以「书籍/作者/章节/原文/前后文/选区」
  分组给出上下文，并附三条要求：先给读音、只解释与语境相符的义项、选区可能不完整时分层解释。
- 提示词是**模板**，支持 20 个占位符：`selection`、`selection_chars`、`context`、`context_before`、`context_after`、
  `sentence`、`fragment_note`、`title`、`authors`、`series`、`language`、`chapter`、`page`、`pages`、`percent`、
  `date`、`time`、`provider`、`model`、`target_language`（`{{word}}` 保留为 `{{selection}}` 的别名，兼容 v0.1 模板）。
- 渲染规则：**没有值的占位符所在行整行删除**（不留「书名：」空壳）；模板中拼错的未知占位符**原样保留**以便发现。
- 菜单提供「插入占位符」子菜单，列出全部占位符及其说明，点选后追加到模板末尾再手动挪位。
- 输出按纯文本处理（剥离思考块与 Markdown 符号），直接进原生查询窗口。

#### 2.3.3 目标语言（2026-10-24 新增）

- 释义用哪种语言回答，是**独立设置项**，与原文语言解耦：读英文书也想看中文解释时，不必改提示词。
- 只给三项：**中文**（默认）/ **英文** / **自定义…**。语言名是自然语言，AI 自己就能理解，
  不必枚举一长串；自定义里写 `日文`、`繁體中文`、`Deutsch` 都行，留空保存则回落到默认中文。
- 存的是语言显示名而非 `zh-CN` 之类的代码——提示词里要给人能读的名字，模型理解更稳。
- 该值以 `{{target_language}}` 注入模板，默认模板第 4 条即「用{{target_language}}解释」。
- 只影响释义语言；读音与词性仍按原文处理（声调拼音 vs 原文拼写/音标）。

#### 2.3.4 思考模式

- **默认关闭思考**（性能优先：关闭思考可大幅降低时延与 token 消耗，Qwen 官方实测可省 60%～75% 耗时）。
- 提供思考配置：**关闭（默认）/ 低 / 中 / 高**。AJBK 统一抽象，按提供商映射为各自的请求参数（映射表见技术调研 §9）。
- 参数上无法关闭思考的模型（如 DeepSeek reasoner 系）：设置页提示改选非思考模型。
- **思考内容永不显示**（2026-09-29 拍板）：无论思考配置如何，响应中的思考内容（`reasoning_content`、`<think>` 块）一律剥离、不进结果窗口；也不提供"显示思考内容"的选项——作为字典没有显示思维链的需要，思考配置只影响回答质量与耗时。

### 2.4 持久化

- 所有设置（提供商列表、密钥、当前提供商、模型、系统提示词、思考模式）持久化到 KOReader **设置目录**内的独立配置文件
  `ajbk_config.lua`（`DataStorage:getSettingsDir()`，LuaSettings 格式，可手工编辑），重启后保留。
- **2026-10-24 变更**：原方案放在插件目录内，代价是升级/重装插件即丢全部配置（插件目录会被整体替换）。
  现改为设置目录，并把路径交给插件管理器的 `settings_file`，删除插件时仍会被一并清理；插件目录内旧配置在首次启动时自动搬迁一次。
- 保存后立即复核配置文件是否真的落盘（设置目录只读时向用户明确报错，而不是静默失败）。

## 3. 技术约束

- 形态：标准 KOReader 插件（`AJBK.koplugin/` 目录，含 `main.lua`、`_meta.lua`），可通过"用户插件目录"安装。
- 实现：全部使用 KOReader 官方插件 API（按钮注册、菜单注册），**不需要**覆盖/monkey patch 内部方法。
- 网络：HTTP 与 HTTPS 均可用（`socket.http` 按 scheme 自动派发，本地 `http://` 服务必须支持）；请求需设置阻塞超时与**总超时**。
- API Key 属敏感信息，仅保存在本机设置文件中，不上传（模型列表拉取、AI 请求除外）；输入框使用密码掩码。
- **性能目标**（低内存电纸书舒适使用）：
  - 不做流式、不做多轮历史；请求期间仅一个可取消的进度框。
  - 结果复用 KOReader 原生查询窗口渲染（无自制 Markdown/HTML 渲染器），输出按纯文本后处理。
  - JSON 解析用 KOReader 自带 C 实现（rapidjson）；HTTP 走 socketutil 的超时与 `table_sink`（后者才执行总超时）。
  - 内置较小的 `max_tokens`（释义场景默认 1024，为"分层解释"与推理模型的思考过程留出余量）与低温度，控制时延与内存占用。服务端拒绝这两个采样参数时自动去掉重试一次。
  - 上下文与元数据全部有字符数上限，不随书籍体积增长。
  - 全部 UI 复用原生 widget；插件自身不驻留大对象。

## 4. 非目标（本期不做）

- 不替换、不禁用内置维基百科（并存）。
- 不做多轮对话、追问。
- 不做全文翻译（KOReader 已自带 Translate 功能）。
- 不修改 KOReader 源码，不做 KOReader 分支。
- 不做查询历史（如需要，后续版本参考 Wikipedia history 实现）。

## 5. 设计决议

| # | 问题 | 决议 |
|---|------|------|
| 1 | 与维基百科的关系 | **并存**：新增按钮与入口，不替换（2026-09-29 拍板） |
| 2 | 提问是否携带选中文本所在句子/段落上下文 | **反转为"是"**（2026-10-24）：默认携带前后文、整句与书籍元数据——电纸书上选区不准，上下文用于判定真实意图与词性语境；不提供开关，靠"无值删整行"保证 PDF 等场景不出空壳 |
| 3 | 是否流式输出（逐段刷新） | **已决**：不做，一次性小响应（性能优先） |
| 4 | 是否查询历史 / 结果保存 | 本期不做 |
| 5 | max_tokens / 超时是否暴露为设置 | **已决**：内置默认（max_tokens 1024、低温度、阻塞 60s / 总 90s），暂不暴露 |
| 6 | 按钮与菜单文案 | 暂定 "AJBK"，可在实现时微调 |
| 7 | 思考模式 | **已决**：默认关闭；提供 关闭/低/中/高 配置，按提供商映射参数（技术调研 §9）；当前提供商无映射时档位置灰 |
| 8 | 产品定位 | **已决**：聚焦"AI 当字典/词典"单一场景，极致性能优先，低内存设备舒适可用（2026-09-29 拍板） |
| 9 | 选区不准如何兜底 | **已决**（2026-10-24）：携带上下文 + 选区粘连自检；自检可疑时提示词要求分层解释（先片段、后完整词条） |
| 10 | 提示词模板能力 | **已决**（2026-10-24）：20 个占位符 + 无值删整行 + 未知占位符原样保留 + 菜单内"插入占位符" |
| 11 | 目标语言 | **已决**（2026-10-24）：中文（默认）/ 英文 / 自定义；以 `{{target_language}}` 注入模板，存显示名不存语言代码 |

## 6. 验收标准

1. 安装插件并重启 KOReader 后：查词窗口底部出现 AJBK 按钮（与 Wikipedia 同级、可在"自定义窗口按钮"中管理）；选中文字弹窗出现 AJBK 项。
2. 点击任一 AJBK 入口，正确发起 AI 请求并在原生查询窗口展示解释。
3. 顶部菜单 → 搜索 → AJBK 打开设置：可新增/切换预设与自定义提供商、填写 Base URL 与 API Key（密码掩码），地址非法时保存前即报错。
4. 模型选择能拉取并展示服务器模型列表（以 OpenAI 兼容服务验证），也可手动输入；选定后子菜单立即刷新并标出当前模型。
5. 系统提示词可编辑、插入占位符、保存、恢复默认；修改后查询行为随之变化；无值占位符所在行不出现在最终提示词里。
6. 断网点击 AJBK 有明确提示；请求失败有可读错误信息；KOReader 不崩溃、不卡死（请求可取消）。
7. 默认配置下请求**携带上下文**（前后文/整句/元数据）但不带思考参数；开启思考配置后参数按提供商正确映射；响应中的思考内容（含多行、未闭合标签）与 Markdown 符号被剥离，窗口显示纯文本释义。
8. 在低内存设备（如 256MB 内存的老款 Kindle/Kobo）上，查询全流程（选词→请求→展示）无明显卡顿、无内存告警。
9. 只选中一个词中的 1～2 个字时，结果先解释该片段、再给完整词条；PDF 查询时提示词不出现空的「原文：」行。
10. 本地 `http://` 服务（Ollama 11434 / LM Studio 1234 / 局域网网关）可正常查询。
