# AJBK.koplugin 需求文档

> AJBK = 「AI 基百科」。以 KOReader 插件形式**新增** AI 查询能力：在查词窗口注册与"维基百科"同级的 AJBK 按钮，在选中文字菜单注册入口；点击后携带系统提示词向 AI 提问并展示解释。**与内置维基百科并存，不替换、不修改 KOReader 源码。**
> 技术实现依据见 [技术调研.md](./技术调研.md)。

## 1. 背景与目标

KOReader 在阅读中选中文字后，可查词典、跳维基百科。国内访问维基百科不便，而对生僻字、成语、文言短句这类需求，AI 释义更直接。

**命名与定位**（2026-09-30 明确）：AJBK = 「AI 基百科」——用 AI 替代维基百科。AJBK 是**本地词典的后备查询工具**：日常查词仍用自带词典；词典查不到的生僻字、网络新词、文言短句、成语典故，或维基百科不可达时，用 AJBK 直接问 AI。

目标：开发 KOReader 插件 `AJBK.koplugin`，在 KOReader 的查询体系中注册 AJBK 入口——用户选中文本后一键向 AI 提问，在原生查询窗口中查看释义。与维基百科并存，用户可各取所需。

**产品定位**（2026-09-29 拍板）：只聚焦一个点——**把 AI 当字典、词典用**，做生僻字、短语、短句的释义问答。不做对话、不做多轮、不做搜索、不做书籍分析（这正是与 assistant.koplugin 等全能型 AI 插件的差异）。一切设计以**极致性能**为先，确保低内存电纸书设备舒适使用：默认不开思考（可配置）、默认不带上下文、一次性小响应、全部复用 KOReader 原生窗口。

## 2. 功能需求

### 2.1 查询入口（三处注册）

1. **查询窗口按钮**（主入口）：查词结果窗口底部注册与 Wikipedia 同级的 AJBK 按钮。走 KOReader 官方按钮注册 API，参与"自定义窗口按钮"体系——用户可在设置中像内置按钮一样勾选、排序或移除它（路径：搜索设置 → 设置 → 词典设置 → 自定义按钮 → 排列并切换按钮）。
2. **选中文字弹窗**：长按划选后弹出的操作菜单（选择/高亮/复制/加注/维基百科/词典/翻译…）末尾注册 AJBK 项。
3. **设置菜单查询入口**（可选，P2）：设置里提供"AJBK 查询"，手动输入词语查询（对齐维基百科 lookup 的体验）。

### 2.2 核心查询流程

1. 点击 AJBK 入口后，将选中文字作为提问内容，**携带系统提示词**向所配置的 AI 提供商发起请求。
2. 请求期间显示进度提示（可取消）；离线时提示需联网（跟随 KOReader 网络管理，联网后可自动重试）。
3. 请求完成后，在 KOReader 原生查询结果窗口中展示 AI 的解释（样式与词典/百科结果一致，来源名显示为 AJBK）。
4. 请求失败（网络错误、超时、鉴权失败等）时给出可读的错误提示。

场景：生僻字读音字义、成语/短语/典故解释、文言文短句释义等。

### 2.3 插件设置菜单

**位置**：顶部菜单 → **搜索** → **AJBK（AI 百科）**（与 词典查询/维基百科查询/生词本 同级，两层可达；`sorting_hint = "search"`，2026-09-29 调整——原"工具 → 更多工具"过深）。界面组件映射与技术选型见 [技术调研.md](./技术调研.md) §7，预设提供商清单见 §8。

包含：

#### 2.3.1 提供商与模型（合并为一个子菜单）

- **预设提供商**：内置 19 家预设（国内/国际站分列），选择后自动填充 API Base URL，用户只需填 API Key。
- **自定义提供商**：可自行填写名称、API Base URL、API Key。
- 接口约定：统一采用 **OpenAI 兼容接口**（`POST {base}/chat/completions`、`GET {base}/models`）。
- 每家已配置提供商一个子菜单，内含：当前模型展示、**测试连接并获取模型列表**（兼 API 配置测试）、手动输入模型名、设为当前提供商、修改 API Key / API 地址、删除。
- **连接测试**：`GET {base}/models`，成功即说明地址与 Key 有效；填写 API Key、API 地址、自定义提供商的对话框内均提供**测试按钮**，可在保存前验证输入值（2026-09-29 增补）。
- 模型列表拉取失败（无网络、地址错误、不支持该接口）时，允许**手动输入模型名**；记住每个提供商上次使用的模型。

#### 2.3.2 系统提示词

- 内置**默认提示词**（原文，用户可查看、编辑并保存；提供"恢复默认"）：

> 你忠实的扮演字典、词典的角色，不要任何废话，像字典一样去写出文字的读音，简单的释义即可。无需展开。现在用户向你查询的内容如下：

- 提示词是**模板**：默认行为是把选中文本追加在提示词末尾（默认提示词以"如下："收尾，正好衔接）；模板内也可用 `{{word}}` 占位符显式指定查询词的插入位置。
- 输出按纯文本处理（剥离思考块与 Markdown 符号），直接进原生查询窗口。

#### 2.3.3 思考模式

- **默认关闭思考**（性能优先：关闭思考可大幅降低时延与 token 消耗，Qwen 官方实测可省 60%～75% 耗时）。
- 提供思考配置：**关闭（默认）/ 低 / 中 / 高**。AJBK 统一抽象，按提供商映射为各自的请求参数（映射表见技术调研 §9）。
- 参数上无法关闭思考的模型（如 DeepSeek reasoner 系）：设置页提示改选非思考模型。
- **思考内容永不显示**（2026-09-29 拍板）：无论思考配置如何，响应中的思考内容（`reasoning_content`、`<think>` 块）一律剥离、不进结果窗口；也不提供"显示思考内容"的选项——作为字典没有显示思维链的需要，思考配置只影响回答质量与耗时。

### 2.4 持久化

- 所有设置（提供商列表、密钥、当前提供商、模型、系统提示词）持久化到**插件目录内的独立配置文件 `ajbk_config.lua`**（LuaSettings 格式，可手工编辑），重启后保留；删除整个插件目录即无残留（2026-09-29 决议，弃用 G_reader_settings 方案）。

## 3. 技术约束

- 形态：标准 KOReader 插件（`AJBK.koplugin/` 目录，含 `main.lua`、`_meta.lua`），可通过"用户插件目录"安装。
- 实现：全部使用 KOReader 官方插件 API（按钮注册、菜单注册），**不需要**覆盖/monkey patch 内部方法。
- 网络：HTTP 请求需设置超时；HTTPS 可用（依赖 KOReader 自带网络栈）。
- API Key 属敏感信息，仅保存在本机设置文件中，不上传（模型列表拉取、AI 请求除外）。
- **性能目标**（低内存电纸书舒适使用）：
  - 不做流式、不做多轮历史；请求期间仅一个可取消的进度框。
  - 结果复用 KOReader 原生查询窗口渲染（无自制 Markdown/HTML 渲染器），输出按纯文本后处理。
  - JSON 解析用 KOReader 自带 C 实现（rapidjson）；HTTP 走 socketutil 超时控制。
  - 内置较小的 `max_tokens`（释义场景默认约 300）与低温度，控制时延与内存占用。
  - 全部 UI 复用原生 widget；插件自身不驻留大对象。

## 4. 非目标（本期不做）

- 不替换、不禁用内置维基百科（并存）。
- 不做多轮对话、追问。
- 不做全文翻译（KOReader 已自带 Translate 功能）。
- 不修改 KOReader 源码，不做 KOReader 分支。
- 不做查询历史（如需要，后续版本参考 Wikipedia history 实现）。

## 5. 设计决议

| # | 问题 | 决议 |
|---|------|------|
| 1 | 与维基百科的关系 | **并存**：新增按钮与入口，不替换（2026-09-29 拍板） |
| 2 | 提问是否携带选中文本所在句子/段落上下文 | **已决**：默认不携带，一期不提供开关（KOReader 有现成 API `getSelectedWordContext`，留作二期可选项，见技术调研 §8.3） |
| 3 | 是否流式输出（逐段刷新） | **已决**：不做，一次性小响应（性能优先） |
| 4 | 是否查询历史 / 结果保存 | 本期不做 |
| 5 | max_tokens / 超时是否暴露为设置 | **已决**：内置默认（max_tokens 约 300、低温度、合理超时），暂不暴露 |
| 6 | 按钮与菜单文案 | 暂定 "AJBK"，可在实现时微调 |
| 7 | 思考模式 | **已决**：默认关闭；提供 关闭/低/中/高 配置，按提供商映射参数（技术调研 §9） |
| 8 | 产品定位 | **已决**：聚焦"AI 当字典/词典"单一场景，极致性能优先，低内存设备舒适可用（2026-09-29 拍板） |

## 6. 验收标准

1. 安装插件并重启 KOReader 后：查词窗口底部出现 AJBK 按钮（与 Wikipedia 同级、可在"自定义窗口按钮"中管理）；选中文字弹窗出现 AJBK 项。
2. 点击任一 AJBK 入口，正确发起 AI 请求并在原生查询窗口展示解释。
3. 顶部菜单 → 工具 → 更多工具 → AJBK 打开设置：可新增/切换预设与自定义提供商、填写 Base URL 与 API Key。
4. 模型选择能拉取并展示服务器模型列表（以 OpenAI 兼容服务验证），也可手动输入。
5. 系统提示词可编辑、保存、恢复默认；修改后查询行为随之变化。
6. 断网点击 AJBK 有明确提示；请求失败有可读错误信息；KOReader 不崩溃、不卡死（请求可取消）。
7. 默认配置下请求不带上下文、不带思考参数（或思考=disabled）；开启思考配置后参数按提供商正确映射；响应中的思考内容与 Markdown 符号被剥离，窗口显示纯文本释义。
8. 在低内存设备（如 256MB 内存的老款 Kindle/Kobo）上，查询全流程（选词→请求→展示）无明显卡顿、无内存告警。
