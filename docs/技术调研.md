# 技术调研：KOReader 维基百科入口机制与插件替换方案

> 基于 KOReader 官方主分支源码（本机参考副本：`F:\ForAI\koreader`，稀疏克隆）。
> 结论先行：**纯事件拦截不可行，需运行时覆盖类方法（monkey patch）**，两个覆盖点即可完成"换按钮 + 换行为"。

## 1. 内置维基百科是怎么注册的

### 1.1 模块本体

`ReaderWikipedia` 不是独立窗口，而是一个"特殊词典"——直接继承词典模块：

```lua
-- frontend/apps/reader/modules/readerwikipedia.lua:24
local ReaderWikipedia = ReaderDictionary:extend{
    is_wiki = true,
}
```

在 `ReaderUI:init()` 中作为内置模块注册（早于任何插件）：

```lua
-- frontend/apps/reader/readerui.lua:226
self:registerModule("wikipedia", ReaderWikipedia:new{ ... })
```

`registerModule`（readerui.lua:94）把实例挂到 `self.wikipedia`（所以别处能 `self.ui.wikipedia` 访问它），并追加进 ReaderUI 子控件表，从而能收到事件、能注册主菜单。

### 1.2 两个用户入口

**入口 A：主菜单项**。`ReaderWikipedia:init()` 调用 `self.ui.menu:registerToMainMenu(self)`（readerwikipedia.lua:35），随后 `addToMainMenu(menu_items)`（readerwikipedia.lua:90）注册三组菜单：

- `menu_items.wikipedia_lookup` — "Wikipedia lookup"（主菜单查询入口）
- `menu_items.wikipedia_history` — 查询历史
- `menu_items.wikipedia_settings` — 维基百科设置（语言、EPUB 保存等）

`ReaderMenu:registerToMainMenu` 只是把 widget 存进 `registered_widgets` 表（readermenu.lua:532）；真正构建菜单时对每个 widget `pcall(widget.addToMainMenu, widget, self.menu_items)`（readermenu.lua:344）。插件注册菜单用的是**同一机制**（见 hello 示例插件 `plugins/hello.koplugin/main.lua:27-44`）。

**入口 B：查词窗口按钮（本次要替换的对象）**。词典弹窗 `DictQuickLookup` 的底部按钮池 `_getButtonPool()`（dictquicklookup.lua:718），其中 wikipedia 按钮定义在 dictquicklookup.lua:839-856：

```lua
wikipedia = {
    id = "wikipedia",
    text_func = function()
        if self.is_wiki then
            return C_("Wikipedia", "Full article")
        else
            return _("Wikipedia")
        end
    end,
    callback = function()
        UIManager:scheduleIn(0.1, function()
            self:lookupWikipedia(self.is_wiki)
        end)
    end,
},
```

### 1.3 所有查询汇聚到同一个事件

无论从哪里触发维基百科查询，最终都发同一个 `LookupWikipedia` 事件：

| 触发点 | 位置 |
|---|---|
| 查词窗口 Wikipedia 按钮 | `DictQuickLookup:lookupWikipedia()` → dictquicklookup.lua:1952，于 1977 行 `self.ui:handleEvent(Event:new("LookupWikipedia", word, is_sane, word_boxes, get_fullpage, lang, dict_close_callback))` |
| 选中文字弹出的菜单里 "Wikipedia" 项 | readerhighlight.lua:159-164、396，`ReaderHighlight:lookupWikipedia()`（2330）发同一事件 |
| 大窗模式重开、语言切换 | 同样走 `LookupWikipedia` 事件（dictquicklookup.lua:1359、883） |

事件唯一消费者：

```lua
-- readerwikipedia.lua:393-399
function ReaderWikipedia:onLookupWikipedia(word, is_sane, box, get_fullpage, forced_lang, dict_close_callback)
    Trapper:wrap(function()
        self:lookupWikipedia(word, is_sane, box, get_fullpage, forced_lang, dict_close_callback)
    end)
    return true   -- ← 消费事件，阻止继续传播
end
```

其内部流程（readerwikipedia.lua:401-534）值得 AJBK 照抄骨架：

1. `NetworkMgr:willRerunWhenOnline(...)` — 离线时挂起、联网自动重试（:402）；
2. `self:cleanSelection(word, is_sane)` — 清洗选中文本（:424，实现在 readerdictionary.lua:1090）；
3. `self:showLookupInfo(display_word)` — 显示"正在查询"进度框（可取消，:455）；
4. HTTP 拉数据（`ui/wikipedia.lua` 用 `socket.http`/`https`，:147；配合 `socketutil` 超时）；
5. 组装结果表 → `self:showDict(word, results, box, nil, dict_close_callback)`（:533，实现在 readerdictionary.lua:1510），结果表元素形如：

```lua
{
    dict = "Wikipedia EN",   -- 来源名（窗口顶部显示）
    word = page.title,       -- 标题
    definition = definition, -- 正文文本
    is_wiki_fullpage = ...,  -- 维基专用标记
    lang = lang,
}
```

## 2. 插件机制（pluginloader.lua）

- **目录约定**：`*.koplugin` 目录内 `main.lua`（返回 `WidgetContainer:extend` 的组件类，PluginLoader 调 `new` 实例化）+ `_meta.lua`（`fullname`、`description`）（pluginloader.lua:174-271）。
- **安装路径**：内置 `plugins/`；用户插件目录默认 `koreader数据目录/plugins/`，也可经设置加 `extra_plugin_paths`（pluginloader.lua:174-200）。
- **实例化**：`ReaderUI:init()` 末尾遍历插件并 `registerModule(plugin_module.name, plugin_instance)`（readerui.lua:463-476）→ 插件实例也成为 ReaderUI 子控件：能收事件、有 `self.ui`、能注册主菜单。
- **事件沙箱**：插件所有 `on*` 处理器被 pcall 包裹，出错只记日志不崩 KOReader（pluginloader.lua:158-164）。
- **模块引用**：插件目录会被加进 `package.path`（pluginloader.lua:285），插件可拆多个 lua 文件 `require` 引用。
- **设置持久化**：直接用 `G_reader_settings`（全局 settings.reader.lua）；插件可声明 `settings_file`/`settings_key` 让插件管理器支持"删除设置"。

## 3. 替换方案结论（备选，最终设计未采用）

> **设计更新（2026-09-29）**：AJBK 最终采用**并存式**注册——不替换维基百科，改用 §6 的官方插件 API 挂载三处入口。本节覆盖方案保留为"替换式"备选。

### 3.1 为什么不能只靠事件拦截

`WidgetContainer:handleEvent` 按子控件**注册顺序**遍历，任一处理器返回 `true` 即停止传播（widgetcontainer.lua:83-86）。内置 `wikipedia` 模块在 readerui.lua:226 注册，插件在 :464 才注册——`ReaderWikipedia:onLookupWikipedia` 永远先收到 `LookupWikipedia` 事件并返回 `true` 消费掉，插件的 `onLookupWikipedia` 根本轮不到。**事件拦截方案否决。**

### 3.2 可行方案：运行时覆盖类方法

Lua 的方法在**调用时**才经元表回类表查找，所以插件在 `main.lua` 顶层覆盖类表上的方法，对"已经实例化的 ReaderWikipedia 单例"同样生效（插件实例化于 ReaderUI:init 期间，远早于用户点击按钮）。两个覆盖点：

```lua
-- AJBK.koplugin/main.lua（示意）
local ReaderWikipedia = require("apps/reader/modules/readerwikipedia")
local DictQuickLookup = require("ui/widget/dictquicklookup")

-- 覆盖点 1：接管全部维基百科查询事件
AJBK._orig_onLookupWikipedia = ReaderWikipedia.onLookupWikipedia
ReaderWikipedia.onLookupWikipedia = function(self, word, is_sane, box, get_fullpage, forced_lang, dict_close_callback)
    -- Trapper:wrap(...) 包住，内部：
    --   NetworkMgr:willRerunWhenOnline → cleanSelection → showLookupInfo
    --   → OpenAI 兼容请求（socketutil 超时）→ 组 results{dict="AJBK", word=..., definition=...}
    --   → self:showDict(word, results, box, nil, dict_close_callback)
    return true
end

-- 覆盖点 2：换按钮文案
local orig_getButtonPool = DictQuickLookup._getButtonPool
DictQuickLookup._getButtonPool = function(self)
    local pool = orig_getButtonPool(self)
    pool.wikipedia.text_func = nil
    pool.wikipedia.text = "AJBK"
    return pool
end
```

要点：

- 覆盖点 1 一处即覆盖**所有**维基百科入口（查词窗按钮、选中菜单项、大窗重开、语言切换、热键），因为都汇聚到 `LookupWikipedia` 事件。
- `self` 就是 `ui.wikipedia` 实例（ReaderDictionary 子类），`cleanSelection` / `showLookupInfo` / `showDict` 可直接复用，展示窗口与词典/百科完全一致。
- 结果表**不要**带 `is_wiki` / `is_wiki_fullpage` 标记，窗口即按词典样式渲染（不会出现"Save as EPUB""Language ≡"等维基专属按钮）。
- 想恢复原行为：保存原函数引用，提供还原/开关能力。

### 3.3 对照：moon 项目的做法

`github.com/AnkioTomas/moon` 是**整个 KOReader 的分支**（仓库约 380MB），直接修改源码把维基百科替换为百度百科。优点是改动自由，缺点是必须跟随上游同步维护、安装的是整个阅读器。AJBK 选择插件路线：单目录安装、升级无耦合。其"按钮文案 + 请求 + 结果窗口"三件套的思路与 3.2 一致。

## 4. 普通用户层面能否禁用内置维基百科？

**结论：没有全局开关，只有一个局部开关。** `ReaderWikipedia` 是内置模块而非插件，插件管理器里看不到它（pluginloader.lua 的 `BUILTIN_PLUGINS` 全是 `.koplugin`），无法像插件一样禁用。逐入口盘点：

| 入口 | 用户能否关闭 | 依据 |
|---|---|---|
| 词典结果窗口的 Wikipedia 按钮 | **能**：设置 → 词典 → 自定义窗口按钮，取消勾选 Wikipedia（存 `dict_button_config`） | readerdictionary.lua:503-517（选项含 wikipedia）、:607（保存） |
| 维基百科自己的结果窗口 | 不能：布局写死（"Wiki has a fixed, non-configurable layout (yet!)"），全页窗口固定为 {Save as EPUB, Close} | dictquicklookup.lua:1021-1027、1041-1043 |
| 选中后自动查询的默认动作 | 只能改默认行为（ask/词典/维基/翻译），不是禁用 | readerhighlight.lua:786（`default_highlight_action`） |
| 长按弹窗里的 "Wikipedia" 项 | 不能：`_highlight_buttons` 写死 | readerhighlight.lua:107 |
| 主菜单 Wikipedia lookup/历史/设置 | 不能：构建菜单时无条件调用各模块 `addToMainMenu` | readermenu.lua:343、:179（`setUpdateItemTable`） |
| Alt+W / Ctrl+W 快捷键 | 能：禁用 hotkeys 插件即消失 | readerwikipedia.lua:41-43 注释 |

对 AJBK 的含义：覆盖 `ReaderWikipedia.onLookupWikipedia` 后，**所有**维基查询路径（按钮、长按弹窗、快捷键、主菜单发起的查询，见 readerwikipedia.lua:80、:127、:572-576 都汇入该方法）实际都会落到 AJBK——效果比任何用户级开关更彻底。唯一残留是主菜单三项的**文案**仍是"Wikipedia"；如需处理，可再包装 `ReaderWikipedia.addToMainMenu`（菜单每次构建都会调用它，改文案/隐藏可动态生效）。

## 5. 参考：hello 插件（菜单注册最小示例）

```lua
-- plugins/hello.koplugin/main.lua（节选）
local Hello = WidgetContainer:extend{
    name = "hello",
    is_doc_only = false,
}

function Hello:init()
    self.ui.menu:registerToMainMenu(self)
end

function Hello:addToMainMenu(menu_items)
    menu_items.hello_world = {
        text = _("Hello World"),
        sorting_hint = "more_tools",  -- 挂到哪个子菜单
        callback = function() ... end,
    }
end
```

AJBK 的设置菜单（提供商/模型/提示词三组子菜单）照此模式注册即可。

## 6. 官方插件注册 API（AJBK 最终采用的三个挂载点）

最终设计为并存式：不覆盖任何方法，全部走 KOReader 官方插件 API。

### 6.1 查询窗口按钮（与 Wikipedia 同级）

```lua
-- 插件 init() 中：内置模块均已注册，self.ui 可用
self.ui.dictionary:addToDictButtons({
    id = "ajbk",
    text = "AJBK",
    menu_text = _("AJBK"),        -- "自定义窗口按钮"列表里显示的名字
    callback = function(lookup)   -- lookup 是 DictQuickLookup 实例
        -- 取词：lookup.word（原始选词）、lookup.is_sane_word、lookup.lookupword（当前展示词）
        -- 清洗：lookup.ui.dictionary:cleanSelection(word, lookup.is_sane_word)
        -- 之后照 ReaderWikipedia 流程：showLookupInfo → AI 请求 → showDict 展示
    end,
})
```

要点（`populatePluginButtons`，dictquicklookup.lua:947-1017）：

- spec 支持字段：`text`/`text_func`、`callback`/`hold_callback`（均传入 DictQuickLookup 实例）、`enable_func`/`enabled`、`show_func`、`conditional`+`row_group`、`insert_first`、`menu_text`。
- 默认追加为布局末行的独立按钮；非 conditional 按钮同时进入"自定义窗口按钮"体系（readerdictionary.lua:521-527）——用户可在词典设置里像内置按钮一样勾选/排序/移除，真正的"同级别"待遇。
- API 本身校验极宽松：只需含字符串 `id`（`addToDictButtons`，readerdictionary.lua:193-198）。

### 6.2 选中文字弹窗按钮

```lua
self.ui.highlight:addToHighlightDialog("08_ajbk", function(this)
    -- this 是 ReaderHighlight 实例
    return {
        text = _("AJBK"),
        callback = function()
            local word = util.cleanupSelectedText(this.selected_text.text)
            -- 发起 AI 请求
        end,
    }
end)
-- 移除：self.ui.highlight:removeFromHighlightDialog("08_ajbk")
```

- 现有键位：`01_select`、`02_highlight`、`03_copy`、`04_add_note`、`05_wikipedia`、`06_dictionary`、`07_translate`（readerhighlight.lua:107-185）→ AJBK 取 `"08_ajbk"`，排在翻译之后。
- API：`addToHighlightDialog(idx, fn_button)` / `removeFromHighlightDialog(idx)`（readerhighlight.lua:1519-1528）；`fn_button(this)` 返回按钮表，按键名排序渲染（:1539 `orderedPairs`）。

### 6.3 设置菜单位置

- KOReader **没有**名为 "plugins" 的菜单挂载点；"插件"管理（`plugin_management`）本身位于 工具 → 更多工具 底部（reader_menu_order.lua:201；菜单项定义 readermenu.lua:300-302）。
- **最终采用 `sorting_hint = "search"`**（2026-09-29 调整，原 more_tools 过深）：阅读菜单的搜索 tab 与 词典查询/维基百科查询/生词本 同级（reader_menu_order.lua:204-214），文件管理器菜单同样有 search 区（filemanager_menu_order.lua:151）——AJBK 作为查询类功能挂在语义最贴切且只有两层的 tab：

```lua
menu_items.ajbk = {
    text = _("AJBK（AI 百科）"),
    sorting_hint = "search",       -- → 顶部菜单 → 搜索 → AJBK
    sub_item_table = { ... },      -- 查询词语 / 提供商与模型 / 思考模式 / 系统提示词
}
```

### 6.4 时序与守卫

- 插件实例在 `ReaderUI:init()` 末尾创建（readerui.lua:463-476），晚于全部内置模块 → 插件 `init()` 里 `self.ui.dictionary`、`self.ui.highlight` 已可用，可直接注册；稳妥起见注册前判空。
- 取词、进度、展示的实现细节照 §1.3 的 ReaderWikipedia 流程（`cleanSelection` → `showLookupInfo` → 请求 → `showDict`）；请求可用 `ui.dictionary:showDict()`（readerdictionary.lua:1510）复用原生结果窗口，`results` 元素 `dict = "AJBK"`、不带 `is_wiki` 标记。
- `show_func`/`enable_func` 可用于后续扩展（如仅对短文本显示）。

## 7. 设置界面的显示方案（组件映射）

KOReader 的插件设置页本质是 **TouchMenu 菜单树**（`addToMainMenu` 的 `sub_item_table`），配合若干弹窗 widget。全部组件均在 `frontend/ui/widget/`，无需自制控件。

### 7.1 可用组件清单（已核对源码）

| 组件 | 用途 | 关键参数/依据 |
|---|---|---|
| TouchMenu 菜单项 | 设置树本体 | `text_func`、`checked_func`+`radio`、`enabled_func`、`keep_menu_open`、`separator`、`help_text`；**`sub_item_table_func` 动态子菜单**（touchmenu.lua:887、1029）——"当前提供商"按已保存列表动态渲染 radio 勾选 |
| InputDialog | 文本输入 | 密码：`text_type="password"`（inputdialog.lua:20，自带明文切换 ：398）；**多行：`allow_newline=true`**（:137）→ 系统提示词编辑；`description` 放说明 |
| MultiInputDialog | 多字段输入 | 一个弹窗填多个字段（multiinputdialog.lua）→ "添加自定义提供商"（名称/Base URL/Key 三项一屏） |
| Menu | 可滚动列表弹窗 | 模型列表选择、提供商管理；用法参照 readerbookmark.lua:722（`item_table = { {text=, callback=} }`） |
| ButtonDialog | 按钮网格弹窗 | 模型少时备用（Wikipedia 语言切换即此实现，dictquicklookup.lua:866-900） |
| KeyValuePage | 键值对页面 | "当前配置概览/关于"（Wikipedia 历史同款，readerwikipedia.lua:131） |
| ConfirmBox | 删除确认 | `text`+`ok_text`+`ok_callback` |
| SpinWidget | 数字选择 | 超时秒数等（预留） |
| InfoMessage / Notification | 反馈提示 | 请求中/成功/失败 |
| NetworkMgr | 联网守卫 | `runWhenOnline(cb)`（拉模型、查词语义）；`willRerunWhenOnline`（readerwikipedia.lua:402 同款） |
| Trapper | 可取消进度弹窗 | `Trapper:wrap` + `setTrapWidget`（readerwikipedia.lua:395、460）——AI 查询进度照抄 |

### 7.2 AJBK 菜单信息架构

```
AJBK（AI 百科）                        （menu_items.ajbk, sorting_hint="search"）
├─ 查询词语           ← InputDialog 手动输入直接查询
├─ 提供商与模型（当前：X）← 合并管理（2026-09-29 调整：模型并入提供商）
│   ├─ 添加预设提供商  ← 列出未添加的预设，选定即入库并弹出 Key 对话框
│   ├─ 添加自定义提供商 ← MultiInputDialog（名称/Base URL/API Key，含"测试"按钮）
│   └─ <各已配置提供商>
│       ├─ 当前模型：Y  ← 信息行
│       ├─ 测试连接并获取模型列表 ← GET {base}/models，成功即配置有效
│       ├─ 手动输入模型名 ← 拉取失败/不提供 /models 的兜底
│       ├─ 设为当前提供商
│       ├─ 修改 API Key ← InputDialog password，含"测试"按钮（测未保存的值）
│       ├─ 修改 API 地址 ← InputDialog，含"测试"按钮
│       └─ 删除该提供商 ← ConfirmBox
├─ 系统提示词
│   ├─ 编辑提示词      ← InputDialog allow_newline=true 多行编辑
│   └─ 恢复默认        ← ConfirmBox
└─ 思考模式           ← 关闭(默认)/低/中/高 radio + 参数映射说明
```

设置读写走**插件目录内的独立配置文件 `ajbk_config.lua`**（`LuaSettings:open(path)` + `flush()`；`main.lua` 在 init 时注入插件路径并声明 `settings_file`，使插件管理器支持"删除设置"；2026-09-29 决议弃用 G_reader_settings，删除插件即无残留；**2026-10-24 修正**：插件目录在升级时会被整体替换，等于每次升级都丢配置，故改放 KOReader 设置目录 `DataStorage:getSettingsDir()`，旧位置的配置在首次启动时自动搬迁一次），菜单项用 `checked_func`/`text_func` 实时反映状态。

## 8. AI 提供商预设（含国内/国际双版本）

统一约定：OpenAI 兼容接口，`POST {base_url}/chat/completions`、`GET {base_url}/models`。
**关键事实：国内提供商的国内/国际站账号与 API Key 普遍互不通用**（智谱、硅基流动、通义、Kimi 均如此），所以预设按"提供商 × 区域"拆成独立条目——用户选哪个条目，就在对应的站注册 Key。

### 8.1 核实后的预设表（2026-09-29）

| 预设条目 | Base URL | /models | 备注 |

### 8.3 现成聚合方案参考（重点：assistant.koplugin）

**同平台成熟参考：[omer-faruq/assistant.koplugin](https://github.com/omer-faruq/assistant.koplugin)（624★）**——与 AJBK 场景高度重合（选中文字问 AI、词典弹窗集成、提示词管理），架构与交互细节最值得借鉴：

- **协议与提供商分离**：`api_handlers/` 按协议分文件（openai / anthropic / gemini / responses），提供商实例只存 `display_name / handler / base_url / api_key / model / additional_parameters`。AJBK 一期只做 OpenAI 兼容可简化为单一 handler，但建议保留此分层，为日后接入 Gemini / Anthropic 原生协议留口。
- **提供商注册表**（`assistant_provider_registry.lua`）：UI 添加的提供商以 JSON 字符串存设置（`ui_providers`），带 **schema 版本号**做向前兼容；与文件式预置提供商启动时合并。UI 添加/编辑用 MultiInputDialog。
- **模型选择器**（`assistant_model_picker.lua`）：RadioButtonTable + 搜索 + 分页的弹窗；每个提供商的选中模型存 `selected_model_<id>`；**带手动输入兜底**（showManualInput）——与本文 §7.2 的设计一致，可直接借鉴交互。
- **连接测试**（`Registry.testConnection`）：Trapper 可取消子进程里发最小请求，判定 HTTP 2xx + 模型回声；失败报告格式化展示协议/URL/模型/HTTP 状态/API 原始错误，**绝不显示 API Key**——AJBK 的"测试连接"照此实现。
- **选词上下文提取**（`assistant_dictdialog.lua`）：用 `ui.highlight:getSelectedSentence()` 取词所在整句（`getSelectedWordContext(50)` 兜底、前后各 <50 词的启发式）——**这正是需求待确认项 #2 的现成答案**，API 已由 KOReader 官方提供（readerhighlight）。
- AJBK 的差异化（也是 assistant 刻意不做的）：维护"国内提供商 × 区域端点"预设表（§8.1）；交互聚焦单次释义而非对话。

**其余聚合参考**（用于核对端点与模型名，或作为进阶路线）：

- [LobeChat](https://github.com/lobehub/lobe-chat)：`src/config/modelProviders/<id>.ts`，每提供商一个文件（`id`/`apiBase` 等），结构化程度最高。
- [Cherry Studio](https://github.com/CherryHQ/cherry-studio)：预置提供商常量在 renderer 侧 config 目录（仓库内搜 `zhipu` / `apiHost` 定位）。
- [LiteLLM 文档](https://docs.litellm.ai)：持续维护的各家 api_base 对照表，明确标注 Global/China 双端点（如 Moonshot）。
- [models.dev](https://models.dev)：机器可读数据集（`api.json`，provider → base URL + 模型表），可用于脚本化核对。
- [one-api](https://github.com/songquanpeng/one-api) / new-api / uni-api：自部署聚合网关路线——把多家上游聚合成一个 OpenAI 兼容端点，高级用户可将 AJBK 的"自定义提供商"直接指向自己的网关。

## 9. 思考模式参数映射与性能实现

需求决议：**默认关闭思考**（可配置 关闭/低/中/高），默认不携带上下文，小 `max_tokens`（约 300）。难点是"关闭思考"在各家 OpenAI 兼容接口里参数不统一（2026-09-29 核实），需要按提供商映射。

### 9.1 参数映射表

AJBK 统一抽象为 `thinking = off(默认) / low / medium / high`，`presets.lua` 每条目带 `thinking_style` 字段决定映射方式：

| 提供商 | thinking_style | 关闭（默认） | 开启 / 级别 |
|---|---|---|---|
| 智谱 GLM（国内/Z.ai） | `thinking_type` | `"thinking": {"type": "disabled"}` | `{"type": "enabled"}` |
| MiniMax | `thinking_type` | 同智谱 | 同智谱 |
| 通义 Qwen（百炼） | `enable_thinking` | `"enable_thinking": false` | `true`（Qwen 无级别细分，仅开/关） |
| SiliconFlow | `enable_thinking` | 同 Qwen3 约定 | `true`；部分模型支持 `thinking_budget` |
| DeepSeek | `model_choice` | **无参数可关**（reasoner 系不能关）→ 引导选 `deepseek-chat` | 选 `deepseek-reasoner` 即开 |
| Kimi | `model_choice` | kimi-k2 默认非思考，选 thinking 版即开（待实测） | |
| OpenAI | `reasoning_effort` | GPT-5.2+ 可 `"none"`；o 系列最低 `"low"`；非推理模型省略参数 | `"low"/"medium"/"high"` |
| OpenRouter | `openrouter_reasoning` | `"reasoning": {"enabled": false}`（真关；`exclude: true` 只是隐藏思维链、**不省 token**） | `"reasoning": {"effort": "low|medium|high"}` |
| Gemini 兼容层 | `reasoning_effort` | 省略参数（待实测） | 映射 reasoning_effort |
| Ollama | 特例 | OpenAI 兼容层传 `enable_thinking=false` 会报错（已知坑）、原生 `think:false` 只在 `/api/chat` 生效 → 兜底：选非思考模型 + 后处理剥离 `<think>` | |
| one-api 等网关 | 无 | 视上游而定 | 参数透传 |

通用兜底：无法真正关闭的模型给设置页提示（建议改选非思考模型）；无论如何响应后处理都剥离思考内容。

### 9.2 响应后处理（纯文本化）

**思考内容永不显示、不提供开关**（2026-09-29 用户确认：字典场景无此需要）——思考配置只影响请求参数，思维链在展示层永远被剥离：

1. 只取 `choices[1].message.content`；忽略 `reasoning_content` / `thinking` 字段。
2. 剥离 `<think>...</think>`（含未闭合残块）。
3. 剥离常见 Markdown 符号（`**`、行首 `#`、反引号）为纯文本——原生查询窗口不渲染 Markdown。
4. 压缩多余空行/空白，适配 e-ink 窗口。

### 9.3 性能实现清单（低内存设备）

- 单请求-单窗口模型：无会话、无历史常驻；请求期间只有一个可取消进度框（Trapper）。
- JSON 用 KOReader 自带 **rapidjson**（C 实现）；HTTP 走 `socketutil` 超时 + 可取消。
- 默认即最快路径：`max_tokens≈300`、低温度、思考关闭（Qwen 实测关闭思考省 60%～75% 耗时）、无上下文、无流式缓冲。
- 展示复用 `ReaderDictionary:showDict` 原生渲染；插件不持有超出窗口生命周期的结果引用。
- 预设表是静态 Lua 文件；运行时读写插件目录内的单一配置文件 `ajbk_config.lua`。
